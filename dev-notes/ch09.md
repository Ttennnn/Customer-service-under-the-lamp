## 阶段：Brainstorm 定稿（2026-11-19）

### 用户这一步发的关键原话

- 总目标：「我要用 Superpowers 模式给客服系统装上眼睛,再把答不上的问题变成改进燃料。」
- 六项功能：接 Langfuse（环境变量 + 编译时挂一次回调，完整 trace 树）；Cost Control（意图进 trace 元数据，按意图统计 token）；数据飞轮三入口（置信度低、selfcheck 不够答、用户 👎，各自标 source，落池带召回快照）；飞轮流水线（标准化、查重、待审队列、人工审核写回）；自动化评估（复用 ch04 评估集，落 `eval_runs` 看趋势）；前端（待审后台页 + 聊天页 👎 接后端）。
- 技术栈定死：Langfuse 开源自部署，数据不出自家服务器。
- 本章不做：低置信度问题按主题归类的微调分类器。
- 过程要求：全程 Superpowers；纯 Prompt/数据任务用标注样例或评估集替代 TDD；前端 Vibe Coding；`dev-notes/ch09.md` 每阶段追记四样，不许收尾一次性补；库/API 先查 Context7；选型矛盾停下来问；完结交付演示命令、测试结果、dev-notes 路径。
- 第一轮选择：「新增独立 compose 栈」「统一调用入口挂载」「加到 ch07 当前页」「只跑 hybrid_rerank」。
- 随后用户发来课程参考 spec，并明确：「参考这份spec文档」；参考 spec 的澄清决策：Langfuse v3、编译期 `with_config` 挂回调、飞轮定时批处理、查重比对 `review_queue` 全部行、👎 前端带 `question` 回捞 checkpointer、方案 A 回调为主、spec 写完整版不逐批确认。
- 设计定稿：「可以」。

### 我的关键产出

- 设计文档：`docs/superpowers/specs/2026-11-19-ch09-observability-flywheel-design.md`（按参考 spec 重写的当前仓库对齐版）。
- 关键路径映射：参考 spec 的 `app/core`/`app/graph`/`app/kb`/`scripts` 映射到现有 `app/agent`、`app/rag`、`app/models`、`app/services`、`app/jobs`；`tests/data/eval_ch04.jsonl` 映射到 `tests/eval/rag_cases.json`（300 条，含 E_multi）。
- Context7 已核实：
  - Langfuse Python SDK v3 的 `langfuse.langchain.CallbackHandler`、`LANGFUSE_PUBLIC_KEY/SECRET_KEY/HOST`、`update_current_trace` 方向、Metrics v2 的 observations 视图与 tags 维度/过滤；v3 自部署 compose 的 Postgres/ClickHouse/Redis/MinIO 环境变量。
  - LangChain `ChatOpenAI(stream_usage=True)` 可在流式调用中回收 usage；自定义 base_url 默认不自动开启。
  - LangGraph 1.2.20 `compile()` 无 callbacks 参数；实测 `compiled.with_config(...)` 返回 `RunnableBinding`，**没有 `get_state`/`get_state_history`**。
- 设计定稿的关键决定：
  - Langfuse v3；`compile().with_config({"callbacks":[CallbackHandler()]})` 编译期挂一次；state 读取用 `_state_graph(graph)` 取 `bound`。
  - 主图知识/退款路径新增 selfcheck 闸：检索 → evidence_confidence → selfcheck → Agent/兜底。
  - `source`：置信度低 `retrieval_low_conf`，selfcheck 不够答 `self_check`，用户反馈 `user_feedback`。
  - `evidence_confidence` 四信号：Top1、有效证据数、Top1-Top2 margin、key_clause_hit；权重固定，阈值用 ch04 评估集 Youden J 校准。

  - 👎 由前端带该轮用户原话，后端从 checkpointer 最近 state 回捞 `retrieved_snapshot`（前 3）；不做 SSE 消息 id 帧。
  - 审核通过用 ch03 的 `insert_mined_qa` + `vectorize_pending` 写回，向量化成功才置通过。

  - Makefile 目标：`langfuse-up/down`、`flywheel`、`cost-report`、`eval-flywheel`、`calibrate-confidence`、`test`；逻辑仍放 `app/jobs`，`scripts/` 只做薄包装。

### 我拒绝或纠偏了什么

- **纠偏「编译时挂回调」与 state 读取的冲突**：`with_config` 后没有 `get_state`；没有为了字面要求删 interrupt/resume，而是加 `_state_graph` 适配层，保留编译期挂回调。
- **按参考 spec 覆盖上一轮口头选择**：v4 → v3；同步落池 → 批处理；只比待审 → 全部行；SSE 消息 id → 前端带 question；selfcheck 只在旧 `/chat` → 主图也加。
- **拒绝把 E_multi 当负例**：ch04 评估集有 E 桶，校准把 A/B/C/E 都算应可答正例，D 才算负例，否则多跳题会被误判为“应拒答”。
- **拒绝伪造校准/验收**：Docker/Milvus/MySQL/Langfuse 当前不可用，校准与 live 验收标记为硬门槛，不用占位数字。
- **拒绝为赶进度复制参考 spec 的旧路径**：没有新建 `app/core`/`app/kb`/`app/graph` 平行结构，全部映射到当前仓库。
- **拒绝在飞轮失败时丢问题**：坏 JSON/幻觉 id/模型异常只跳过、游标停留、下轮重试；low_confidence 行保留。
- **拒绝把 infra/rerank 失败落池**：只对 `retrieval_low_conf` 与 `self_check` 落池；selfcheck 异常/超时保守兜底不落池。
- **拒绝自动通过审核**：通过必须人工填核准答案，且向量化成功才置通过。

### 翻车与返工

- 第一版设计按 v4 + 手动 span + 同步飞轮写，用户发来课程参考 spec 后整份重写为 v3 + 编译期回调 + 批处理对齐版；无代码翻车（仍在设计阶段）。
- 独立 builder 预审 subagent 卡在读代码上超时，被停止；按同一份 builder 清单做了自查，补了 trace 线程安全与飞轮 LLM 注入两处，后随参考 spec 重写再次收口。
- 一次工具检查发现 `RunnableBinding` 没有 `get_state`，促成 `_state_graph` 适配决定。

### 验证证据
