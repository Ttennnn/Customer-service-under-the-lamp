### 用户这一步发的关键原话

- 「我要用 Superpowers 模式给客服系统建知识库,把 query_faq 的内部实现从关键词查表升级成向量语义检索,工具的入参出参契约保持不变。」
- 功能需求原文要点:离线建库文档处理(按标题层级结构感知切分、超长递归切、块间重叠且裁到最近句号、大表格按行切且每块复制表头);离线对话挖知识(定时任务、分批喂 LLM 抽问答对、暂存表、整体去重入库);落库结构(category / questions / answer 三字段拼文本做向量化;商品 FAQ 与挖矿 QA 填真实问法;政策手册填章节标题 + 上级标题路径;章节路径 / 内容类型 / 关键条款 / 前后块指针只存不进向量);双写 MySQL + Milvus、先 pending 后回填、按主键幂等可重跑;在线检索 Top-K 替换 query_faq。
- 技术栈原话要点:BGE-M3、Milvus、MySQL 原文权威源;本章不做关键词召回 / 混合检索 / 重排。

- 工作方式原话要点:全程 Superpowers、技能自动触发;非可单测任务用标注样例/评估集替代 TDD;每个阶段补 dev-notes 四件事;库/框架/API 先过 Context7;技术选型定死,走不通停下问;完结交付演示命令、测试结果、dev-notes 路径。

- 「用云端的」(BGE-M3 不走本机,走云端)。
- 「硅基流动」+ 提供了 API key(仅写入本地 `.env`,不记录在本文件,也不进版本库)。

### 我的关键产出

- 设计文档:`docs/superpowers/specs/2026-11-12-ecommerce-cs-ch03-rag-design.md`。
- Context7 核实:硅基流动 `POST /v1/embeddings` 支持字符串数组批量,`BAAI/bge-m3` 单条上限 8192 token;pymilvus 3.0.3 ↔ Milvus 3.0.x,`MilvusClient` 的 `create_collection` / `upsert` / `search` 签名;Milvus standalone 官方 Compose 为 etcd + MinIO + milvus 三容器。
- 云端连通性实测:真实 key 调用成功,返回 1024 维;「邮费是多少」vs 运费说明 cosine **0.7037**,vs 退货政策 **0.4665**;0.35 阈值作为保守起点,待评估集校准。
- builder 预审(独立 subagent)提出 4 个问题,均在文档内落成明确决定:
  1. `--reset` 只清文档域、保留 `mined_qa`;清全部需显式 `--reset-all` + 二次确认。
  2. `query_faq` 在线超时单独放宽到 8 秒(其余工具仍 5 秒),不改工具契约。
  3. staging 无 category 列,category 只在单次进程内存;重跑先清本次 `source_ref` 的 `extracted` 行再重抽,最终靠内容指纹幂等。
  4. 真实云端嵌入已可用,评估/验收走真实 BGE-M3,不用 fake 代替。
- 设计定稿的关键决定:4 份样本文档、500/80 切块参数、`category\nquestions\nanswer` 向量文本、Milvus 主键 `chunk_{id}` + upsert、FLAT/COSINE、Top-3 + 阈值可调、精确 + 余弦 0.92 两道去重、三个独立 job 命令。

### 我拒绝或纠偏了什么

- **纠偏我自己的初始假设**:最早默认 BGE-M3 在本机跑,用户明确「用云端的」,已切换为硅基流动 API,并实测通过。
- **拒绝 in-process APScheduler**:预审前的默认方案是 FastAPI 内挂定时任务,用户要求「搞一个命令能启动的job就行」,已改为独立 CLI job,部署/触发交给使用方。
- **builder 预审的 4 个问题未升级给用户**:判断均可由实现方用安全默认解决(尤其是 `--reset` 的数据安全边界),按 Superpowers 的「我的 call」处理并在设计文档中显式标注。
