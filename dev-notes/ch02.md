### 翻车与返工

- **【Critical,已修 commit 8003513】contextvar 跨线程 reset 崩溃 → 每条 SSE 尾部多一个 error 帧**。`app/services/chat.py` 的 `stream_chat` 是同步生成器,`EventSourceResponse` 经 Starlette `iterate_in_threadpool` 消费,每次 `next()` 可能落在不同线程池线程:`current_conversation_id.set(cid)`(首个 `next()` 的线程)与 `finally` 里的 `current_conversation_id.reset(token)`(最后一个 `next()` 的线程)不在同一 Context,`contextvars.Token` 只能在其创建时的 Context 中 reset → 抛 `ValueError: Token was created in a different Context`。异常在答案全部流完之后才从生成器冒出,被 `/chat` 的 `except` 兜成一条多余的 `{"error":"客服服务暂时不可用,请稍后重试"}` 帧,且每次请求都打一条 traceback。连带隐患:executor 的 `ctx = copy_context()` 若发生在「set 未生效的线程」上,`create_ticket` 会读到 `None`。
  - **修法**:删掉顶层的 `set(cid)` 与 `finally` 里的 `reset(token)`(不再跨 `yield` 依赖 thread-local contextvar);改为在工具循环内、`execute_tool` 调用**之前** `current_conversation_id.set(cid)`(与 `execute_tool` 之间无 `yield`,必在同一 `next()` 同一线程),使 `copy_context()` 能捕到 cid;每次请求在每次工具调用前重设,无需 reset。另在 `append_message(assistant, tool_calls=...)` 之后补一条 `session.commit()`(否则调用方 session 未提交的 INSERT 占住 SQLite 写锁,`create_ticket` 自开会话会报 `database is locked`)。
  - **回归测试**:新增 `test_create_ticket_receives_cid_across_threads` —— 主线程 `next()` 取到工具帧后,把剩余迭代放到另一 `threading.Thread` 里排干,断言不抛异常且 `Ticket.conversation_id == cid`。RED 精确复现 `ValueError`(跨线程 reset),GREEN 后全量 63 过。
  - **端到端复核**:修后重跑验收 1,SSE 干净 —— 只有 `query_logistics` 工具帧 + 逐 token 答案 + `[DONE]`,无 error 帧、无 traceback。
- **【验收 3 非确定】漏召回场景模型表现漂移**。三次尝试出现三种行为(二次检索/不调工具/正确转人工),温度 0.7 下「如实说未查到 + 引导转人工」命中率约 1/3。若下一步要稳定该场景,可考虑在工具未命中返回里直接带「建议转人工」的强措辞,或降温度/固定提示。
