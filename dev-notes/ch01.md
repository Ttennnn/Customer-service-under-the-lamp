## 阶段:Task 6 完成(结构化提取服务)

### 用户这一步发的关键原话

- (无)

### 我的关键产出

- `app/services/extract.py`(`EXTRACT_SYSTEM_PROMPT` + `extract_after_sale(llm, text) -> AfterSaleExtraction`)+ `tests/test_extract.py`(2 测试)。
- **方法选择结论(`with_structured_output` 的 `method`)**:选 `method="json_mode"`。
  - 经 Context7 查证 DeepSeek 官方文档:`/chat/completions` 的 `response_format.type` 枚举只有 `text` / `json_object`,并明确要求 prompt 中出现 "json"、给出 JSON 示例、设置合理 `max_tokens`。
  - 关键纠偏:计划里默认方法写的是 `function_calling`,但实测安装的 langchain-openai **1.7.4** 中 `ChatOpenAI.with_structured_output` 的默认 `method` 已是 **`json_schema`**(0.3.0 起改动,见 `chat_models/base.py` 第 3886 行),而 `json_schema` 会发 `response_format={"type":"json_schema", ...}`,DeepSeek 的 chat-completions 不支持 → 默认值大概率翻车。
  - DeepSeek 的 `strict` 工具调用是 Beta 功能且要求 `base_url=.../beta` + 所有工具 `strict=true` + `additionalProperties:false`,普通 `function_calling` 虽可用但非 DeepSeek 文档主推;`json_mode` 正是 DeepSeek 明确文档化的 `json_object` 路径,故选用之,并把 JSON 输出要求写进 `EXTRACT_SYSTEM_PROMPT`。
  - Task 8 将用真实 DeepSeek 模型复核此结论。

### 我拒绝或纠偏了什么

- 纠偏了计划中"默认 `function_calling`"的假设(实际默认是 `json_schema`,且不兼容 DeepSeek),并显式传 `method="json_mode"`;测试 FakeLLM 签名改为 `with_structured_output(self, schema, **kwargs)` 以接收 `method`。
