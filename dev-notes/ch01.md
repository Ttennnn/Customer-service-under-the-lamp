## 阶段:Brainstorm 定稿(2026-11-11)

### 用户这一步发的关键原话

- "我要用 Superpowers 模式做一个电商智能客服系统,第一步先跑通纯对话。"
- 功能需求:对话接口(多轮 + SSE 流式逐 token)、Prompt 管理(PromptTemplate 模板化、客服角色设定 + 行为约束)、结构化输出(订单号 / 诉求类型 / 期望方案,`with_structured_output`)、多轮上下文最简版(历史裁剪 + token 预算)。
- 技术栈:Python + FastAPI + LangChain;模型直连上游,应用侧统一 OpenAI 协议,地址/模型名/密钥全在 .env,GPT/Claude/DeepSeek/Ollama 都能换着接。
- 本章不做:工具调用、Agent 循环。
- "我有 deepseek 的 api 可以接入"。
- "1. 是固定枚举,2. 是的"(诉求类型固定枚举;结构化输出是独立接口)。
- "多轮对话怎么标识同一个会话? = session_id + 内存历史"。
- "可换模型这一章要不要真切换验证? = 只做配置化,不真切换"。
- "这份设计文档可以定稿吗?可以"。

### 我的关键产出

- 设计文档:`docs/superpowers/specs/2026-11-11-ecommerce-cs-ch01-conversation-design.md`。
- 经 Context7 查证 DeepSeek 官方文档:base_url `https://api.deepseek.com`、OpenAI 协议兼容、支持 JSON mode / function calling / SSE 流式(`stream=True`),模型名有 `deepseek-chat` / `deepseek-flash`。
