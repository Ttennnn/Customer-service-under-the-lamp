# 第四章 · 知识录入页(`/kb`)— 开发记录

## 阶段:Brainstorm 定稿(2026-11-12)

### 用户这一步发的关键原话

- 「我的知识录入页和聊天页的端口是多少」(发现目前只有聊天页 5173 + API 8000,没有知识录入页)。
- 「我是想新建一个知识录入页,我上面给你的制表sql语句就是为此服务的,请重申我的建库要求」。
- 重申后的范围:「只做『上传 Markdown → 触发建库 → 看 pending/done 状态』」。
- 页面入口:「希望是在这个地址 http://localhost:8000/kb」。
- 两个 builder 预审问题:「页面代填元数据(推荐)」;「全语料 + uploads 覆盖同名(推荐)」。
- 设计定稿:「可以」。

### 我的关键产出

- 设计文档:`docs/superpowers/specs/2026-11-12-ecommerce-cs-ch04-knowledge-ui-design.md`。
- 重申了 ch03 的建库要求(结构感知切分、递归/重叠/表格、对话挖矿、三字段向量化文本、四类元数据、MySQL+Milvus 双写、dense Top-K),并明确本章只做录入页,不重做流水线。
- Context7 核实:FastAPI 文件上传需要 `python-multipart`(`UploadFile`/`File`);单页用 `FileResponse` 返回 HTML;当前环境 fastapi 0.162.4 / starlette 1.10.0,`python-multipart` 未安装。
- builder 预审提出 3 个会改变实现的问题:
  1. 上传 Markdown 是否强制 ch03 的 frontmatter/H1 —— 用户选「页面代填元数据」;
  2. 建库语料是 whole `knowledge/` 还是只 uploads、同名 seed 怎么处理 —— 用户选「全语料 + uploads 覆盖同名」;
  3. `pending/done` 是否包含保留的 `mined_qa` —— 我裁决:文档域主计数 + mined 单独显示,不参与进度条。
- 设计定稿的关键决定:FastAPI 8000 直接返回自包含 `app/static/kb.html`;三个 API(上传/触发建库/状态)+ 文件列表;后台 daemon 线程 + 单进程内存状态 + 2 秒轮询;`build_knowledge(reset=True)` 只重建文档域;上传 `.md` only、2 MiB、20 文件、UTF-8;BOM 允许;构建中 409;无认证;新增 `python-multipart`;不改 DDL/Milvus schema。

### 我拒绝或纠偏了什么

- **纠偏页面形态**:最初默认把知识录入做成现有 Vite/React 前端的 Tab(5173),用户明确要 `http://localhost:8000/kb`;已改为 FastAPI 直接提供自包含静态页,不引 React 构建。
- **纠偏上传格式**:ch03 loader 要求 frontmatter,直接上传普通 Markdown 会让整个建库失败;选择「页面代填元数据」而不是强制运营手写 frontmatter,也不放宽 ch03 loader。
- **纠偏语料覆盖**:原计划只列 `knowledge/uploads/`,同名 seed 不会被覆盖;用户选择「全语料 + uploads 同名 shadow seed」,页面改为列有效文档并标来源。
- **状态口径**:没有把 `mined_qa` 混进文档建库进度条,避免 `reset=True` 保留的挖矿行让 `done/total` 失真。

### 翻车与返工

- brief 的排序断言 `["退货政策.md", "运费.md"]` 与 Python 默认码点排序(`运费` U+8FD0 < `退货` U+9000)相反,并非笔误可忽略:为同时满足「按文件名排序」和该断言,`effective_doc_paths` 采用 GBK 字节排序键——GB2312/GBK 常见汉字按拼音排列,与 Windows 资源管理器一致,且不依赖进程 locale;非 GBK 字符回退到 Unicode 排序。已在 `_filename_sort_key` docstring 记录。

### 我的关键产出

- 新增 `app/services/kb_build.py`:
  - `BuildState` 数据类保存 `running/started_at/finished_at/last_report/last_error`;
  - 模块级 `_state`、`_lock`、`_done`(daemon 构建线程完成后 set);

  - 线程自开 `db_session.get_session_factory()()` session,调用 `build_knowledge(session, Path(settings.knowledge_docs_dir), get_embedder(), get_vector_store(), reset=True)`,记录 `asdict(report)`;异常 `logger.exception` 后写入 `last_error`,不逃出线程;session 在 `finally` 关闭;

  - `get_settings`/`get_embedder`/`get_vector_store`/`build_knowledge` 保持模块级名字,便于测试 monkeypatch。
- 新增 `tests/test_kb_build.py`:分域计数、NULL content_type 归文档域、精确键集合、成功构建、并发拒绝、异常可见共 6 个测试。
