## 阶段:Brainstorm 定稿(2026-11-16)

### 用户这一步发的关键原话

- 总目标:「我要用 Superpowers 模式把客服系统的检索质量做上一个台阶:混合检索加重排,再配一套评估体系。」
- 检索要求:「关键词召回这条路也落在 Milvus 上,用它 2.5 版起原生的 BM25 全文检索,text 字段挂 BM25 函数,中文分词用内置 chinese analyzer;检索时 dense 向量和 BM25 各召回 Top-50,用 hybrid_search 配 RRF 融合。」
- 重排要求:「用 bge-reranker-v2-m3 精排出 Top-10;组装进 prompt 时把最相关的放首尾,别按分数顺序堆中间。」
- 元数据过滤:「支持按品类这类字段先过滤再检索。」
- Query 理解:「口语模糊问法改写归一成标准问法;同义词扩展只在检索侧做,不在入库侧拆存多份。」
- 生成质量控制:「回答带引用编号,编号能映射回来源 chunk 的章节路径、跳回原文;检索不到或证据置信度低就显式拒答;生成阶段让模型自评召回的知识够不够答这个问题,不够则拒答,并把问题落进低置信度问题池;System Prompt 列明禁止承诺的负面知识,比如不承诺到账时间。」
- 评估要求:「造一份带难度梯度、标注 ground-truth 的评估集;检索段评 Recall@K、MRR,生成段评 Faithfulness;跑纯向量、纯 BM25、混合、混合加 Rerank 四种策略的对比,按 query 类型分桶出报告。」
- 前端要求:「回答里的引用编号做成可点的,点开能看到来源 chunk 的原文和章节路径;再给每段回答的左下角挂一组满意度反馈(👍/👎),用户点一下就点亮所选、显示『已反馈』并一次性锁定——这条信号先做纯前端采集,为后面的数据飞轮留一个入口。」
- 章节归属:「让 ch04 让给本章,将知识录入页并回第三章。」
- 设计反馈:「没有偏,按你推荐的来。」(四策略生成段 Faithfulness 全部跑,不只跑最终策略。)
- 设计定稿:「确定。」

### 我拒绝或纠偏了什么

- **纠偏章节号冲突**:仓库已有 `dev-notes/ch04.md` 是知识录入页,与本次「ch04 RAG 进阶」冲突;没有擅自并存,先问用户,按「ch04 让给本章、知识录入页并回第三章」执行。
- **拒绝让 LLM 猜过滤值**:精确匹配的 `category` 若由改写模型自由生成,会把「退款」猜成不存在的品类并清空候选;改为只认显式参数/评估集过滤。
- **拒绝把 infra 失败写进低置信度池**:超时、Milvus/嵌入/自评宕机不是知识缺口;只拒答 + 记日志,池子保持干净。
- **拒绝混合意图整轮拒答**:订单/物流已经查到时,不能因为知识部分不足把有用答案一起丢掉;改为只对知识部分加「无法确认」约束。
- **拒绝用 chunk 计数 Recall**:同一 `section_path` 可能被切成多个 chunk;按 section 去重,避免 Recall 超过 1 / 重复计分。
- **拒绝把 rerank fallback 当 hybrid_rerank 结果**:重排失败必须标记并从该策略聚合中剔除,否则四策略对比失真。
- **拒绝为了「引用可控」改回非流式生成**:流式无法回滚已发 token;用前端只渲染合法编号 + 评估量化 `citation_validity` 的折中,不引入第二个生成通道。
- **未新增产品决策项给用户**:builder 的 7 个问题均可在设计内用安全默认解决;唯一偏产品行为的是混合意图处理,已按「不丢有用结果」裁决并写入 spec。
